# Ockta-docks

> **Интеллектуальная система и AI-агент для автоматизированной генерации академических отчетов по ГОСТ 7.32 в форматах Microsoft Word (`.docx`) и LibreOffice Writer (`.odt`).**

---

## 📋 О проекте

**Ockta-docks** — это специализированный рабочий фреймворк и регламент для автономных мультимодальных AI-агентов (в среде Antigravity CLI, IDE и других агентных платформах), созданный для автоматической подготовки и верстки официальных академических документов:
- **Лабораторных работ**
- **Практических заданий**
- **Отчетов по практикуму и НИР**
- **Курсовых и расчетно-графических проектов**

Система полностью снимает рутину оформления: агент автоматически считывает методические указания (в форматах PDF, Word или HTML), анализирует скриншоты терминала и GUI-инструментов, интегрирует конфигурационные файлы и исходный код, подставляет метаданные и формирует безупречный отчет строго по правилам **ГОСТ 7.32** в выбранном формате — **`.docx`** или **`.odt`**.

---

## ✨ Ключевые возможности

- 📄 **Два целевых формата документа:**
  - Генерация отчетов в **Microsoft Word (`.docx`)** и **LibreOffice Writer (`.odt`)**.
  - Перед началом работы агент обязательно запрашивает у пользователя требуемый формат.
- 🎯 **Автоматическое определение активной работы:**
  - Сканирование каталога `Input/` и автоматический выбор директории с наибольшим номером (`CURRENT_TARGET`).
- 🤖 **Интерактивный мастер метаданных (Smart Fallback):**
  - Если в папке работы отсутствует локальный файл `information.txt`, агент не завершает работу ошибкой, а интерактивно опрашивает пользователя:
    1. **Дисциплина и преподаватель:** выбор номера из единого справочника `Input/lessons.md` (или `lessons.txt`) либо ручной ввод.
    2. **Тип работы:** лабораторная, практическая, квалификационная работа или пользовательский тип.
    3. **Номер и тема работы:** автоматическое извлечение из задания либо уточнение у пользователя.
    4. **Студент и ВУЗ:** подтягивание из глобального `Input/information.txt` или интерактивный ввод.
- 📚 **Единый справочник дисциплин (`lessons.md` / `lessons.txt`):**
  - Удобный реестр предметов, преподавателей, их должностей и ученых званий для быстрого выбора без повторного ввода.
- 👁️ **Мультимодальный анализ скриншотов (`images/`):**
  - Извлечение выполненных команд, параметров, сетевых адресов и статусов из скриншотов консоли.
  - Анализ окон IDE и GUI (формы, настройки, топологии, графики).
  - Хронологическая вставка иллюстраций в текст с подписями по стандарту (*«Рисунок 1 — ...»*) и обязательными ссылками в теле отчета.
- 🧩 **Синтез сопутствующих материалов (`extra/`):**
  - Извлечение ключевых конфигураций, скриптов (`.py`, `.sh`, `.yaml`, `.json`), диагностических логов (`.log`) и табличных данных (`.csv`, `.xlsx`).
- ⚡ **Строгие академические правила для консольных команд:**
  - **Без таблиц:** команды никогда не помещаются в таблицы.
  - **Без шелл-промптов:** автоматически удаляются префиксы консоли (`$ `, `# `, `root@srv:~# `, `PS >`, `C:\Users\...>` и т.д.).
  - **Каждая команда с новой строки:** четкое пошаговое разделение команд.
  - **Курсивное начертание:** все исполняемые команды выделяются *курсивом*.
- 📐 **Строгая академическая типографика (ГОСТ 7.32):**
  - Лист А4, стандартные поля (Левое — 30 мм, Правое — 15/10 мм, Верхнее — 20 мм, Нижнее — 20 мм).
  - Шрифт: Times New Roman / Liberation Serif, 14 pt (или 12 pt по шаблону), полуторный интервал (1.5), абзацный отступ 1.25 см, выравнивание по ширине.
  - Оформление таблиц (*«Таблица 1 — ...»*) и перенос шапок таблиц при разрыве страниц.

## 📚 Формат справочника `Input/lessons.md`

Справочник дисциплин размещается в корне папки `Input/` (поддерживаются файлы `lessons.md` и `lessons.txt`). Каждая дисциплина описывается структурированным блоком:

```markdown
# Справочник учебных дисциплин и преподавателей

---
Дисциплина: Архитектура вычислительных систем
ФИО Преподавателя: Иванов Иван Иванович
Инициалы преподавателя: Иванов И. И.
Должность: Доцент, к.т.н.

---
Дисциплина: Сетевые технологии
ФИО Преподавателя: Петров Петр Петрович
Инициалы преподавателя: Петров П. П.
Должность: Старший преподаватель
```

Если для работы не задан локальный файл `information.txt`, агент отобразит список дисциплин из этого справочника в виде нумерованного меню для быстрого выбора.

## 🚀 Быстрый старт

### Шаг 1. Заполните общие метаданные
В файле [`Input/information.txt`](Input/information.txt) укажите общие сведения об учебном заведении и студенте:

```yaml
institution:
  full_name: "ФГБОУ ВО «Государственный технический университет»"
  short_name: "ГТУ"
  faculty: "Факультет информационных технологий"
  department: "Кафедра вычислительных систем"

student:
  full_name: "Иванов Иван Иванович"
  short_name: "Иванов И. И."
  group: "ИС-41"

location:
  city: "Москва"
  year: "2026"
```

### Шаг 2. Заполните справочник дисциплин
В файле [`Input/lessons.md`](Input/lessons.md) добавьте предметы и преподавателей текущего семестра.

### Шаг 3. Подготовьте материалы новой работы
Создайте в папке `Input/` директорию с новым максимальным номером (например, `Input/3/`):
- `Input/3/images/` — поместите скриншоты выполнения (консоли, GUI, графики).
- `Input/3/extra/` — добавьте конфиги, логи или код.
- `Input/3/Work.pdf` (или `.docx`, `.html`) — методические указания или текст задания.

### Шаг 4. (Опционально) Создайте локальный `information.txt`
Если вы хотите жестко зафиксировать параметры работы без интерактивного опроса, создайте `Input/3/information.txt`:

```yaml
assignment:
  discipline: "Сетевые технологии"
  work_type: "Лабораторная работа"
  work_number: "3"
  work_topic: "Настройка статической маршрутизации и протокола OSPF"
  variant: "5"

instructor:
  title: "Старший преподаватель"
  full_name: "Петров Петр Петрович"
  short_name: "Петров П. П."
```

Если этот файл не создан, агент автоматически запросит данные в интерактивном режиме.

### Шаг 5. Запустите генерацию через AI-агента
В агентной среде (например, Antigravity CLI) дайте команду на создание отчета. Агент выполнит процесс в соответствии с регламентом [`AGENT.md`](AGENT.md):
1. Запросит желаемый формат документа (`.docx` или `.odt`).
2. При необходимости предложит выбрать дисциплину из `lessons.md`.
3. Исследует скриншоты и сопутствующие файлы.
4. Сформирует титульный лист, цель, теоретическую часть, пошаговый ход работы, ответы на вопросы и вывод.
5. Сохранит готовый файл в каталоге `Output/[N] - [Тема]/`.

## 📑 Стандартная структура отчета

1. **Титульный лист:** полное оформление реквизитов организации, кафедры, исполнителя и проверяющего (без колонтитулов и номеров страниц).
2. **Цель и задачи работы:** четкая академическая постановка на основе методички.
3. **Краткие теоретические сведения:** сжатый теоретический базис, относящийся строго к теме работы.
4. **Ход выполнения работы (Практическая часть):**
   - Пошаговое повествование в безличном стиле (*«было выполнено конфигурирование...»*).
   - Выполненные команды отдельными абзацами в *курсивном* начертании (без таблиц и без шелл-промптов).
   - Встроенные иллюстрации с подписями (*«Рисунок [N] — [Описание]»*) и обязательными ссылками в тексте.
5. **Ответы на контрольные вопросы** (если содержатся в задании).
6. **Вывод:** глубокий технический итог, соотносящийся с поставленными целями.
7. **Список использованных источников / Приложения** (при необходимости).

## ⚙️ Требования к форматированию (ГОСТ 7.32)

| Параметр | Требование стандарта |
|---|---|
| **Формат документа** | `.docx` (Microsoft Word) или `.odt` (LibreOffice Writer) |
| **Формат страницы** | A4, книжная ориентация (Portrait) |
| **Поля страницы** | Левое: 30 мм, Правое: 15 мм (или 10 мм), Верхнее: 20 мм, Нижнее: 20 мм |
| **Основной шрифт** | Times New Roman / Liberation Serif, 14 pt (или 12 pt по шаблону) |
| **Межстрочный интервал** | Полуторный (1.5) |
| **Абзацный отступ** | 1.25 см |
| **Выравнивание** | По ширине (Justified) |
| **Оформление команд** | Без таблиц, без шелл-промптов (`$`, `#`), отдельная строка, стиль *курсив* |
| **Подписи к рисункам** | По центру под рисунком: *«Рисунок X — Название»* (12 pt, одинарный интервал) |
| **Подписи к таблицам** | Над таблицей с выравниванием по левому краю: *«Таблица X — Название»* |

## 🛠️ Зависимости и инструменты

Для генерации документов и манипуляций с данными используются:
- **Python 3.10+**
- **`python-docx`** — создание и редактирование отчетов `.docx`
- **`odfpy`** — создание и редактирование отчетов `.odt`
- **`Pillow`** — обработка и анализ скриншотов
- **`pypdf` / `pdfplumber`** — извлечение текста и таблиц из PDF-заданий
- **LibreOffice** (`soffice --headless`) — опционально для конвертации форматов
