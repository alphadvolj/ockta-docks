# Ockta-docks

> **Автоматизированная система и агент генерации академических отчетов по ГОСТ 7.32 в формате Microsoft Word (`.docx`).**

---

## 📋 О проекте

**Ockta-docks** — это специализированный рабочий фреймворк и набор инструкций для мультимодальных AI-агентов (в среде Antigravity CLI, IDE или других агентных средах), предназначенный для автоматической сборки официальных академических отчетов:
- **Лабораторных работ**
- **Практических заданий**
- **Отчетов по практикуму**
- **Курсовых и расчетно-графических работ**

Система избавляет от рутинного ручного оформления: агент автоматически считывает методические указания, интерпретирует скриншоты консоли и интерфейсов, синтезирует исходный код и логи, заполняет титульные листы по метаданным и форматирует документ строго в академическом стиле по правилам **ГОСТ 7.32**.

---

## ✨ Ключевые возможности

- 🎯 **Умное определение активной работы:** агент автоматически сканирует каталог `Input/` и выбирает директорию с максимальным числовым номером (`CURRENT_TARGET`).
- 👁️ **Мультимодальный анализ скриншотов (`images/`):**
  - Распознавание команд и выводов терминала (stdout/stderr, IP-адреса, статус сервисов).
  - Определение состояния GUI/IDE (активные окна, настройки, формы).
  - Автоматическая расстановка рисунков по тексту с подписями по стандарту (*«Рисунок 1 — ...»*).
- 🧩 **Интеграция сопутствующих материалов (`extra/`):** выжимка ключевых фрагментов кода (`.py`, `.sh`, `.cpp`, `.json`), логов (`.log`) и структурированных данных (`.csv`, `.xlsx`).
- 📐 **Строгая академическая типографика (ГОСТ):**
  - Формат А4, стандартные поля (Левое — 30 мм, Правое — 15/10 мм, Верхнее — 20 мм, Нижнее — 20 мм).
  - Шрифт: Times New Roman, 14 pt (или 12 pt по шаблону), интервал 1.5, абзацный отступ 1.25 см, выравнивание по ширине.
- ⚡ **Специальные правила для консольных команд:**
  - **Без таблиц:** команды никогда не помещаются в ячейки таблиц.
  - **Без шелл-промптов:** вырезаются `$ `, `# `, `root@srv:~# `, `PS >` и т.д.
  - **Новая строка и курсив:** каждая команда оформляется отдельной строкой и выделяется *курсивом*.
- 🏢 **Иерархическая система метаданных:** разделение общих данных (ВУЗ, студент, город) и параметров конкретной работы (дисциплина, преподаватель, тема, вариант).

## 🚀 Быстрый старт

### Шаг 1. Заполните общие метаданные
В файле [`Input/information.txt`](file:///C:/Users/dvolj/Desktop/Ockta_docs%20git/Input/information.txt) укажите данные учебного заведения и студента:

```yaml
institution:
  full_name: "ФГБОУ ВО «Московский государственный технический университет»"
  short_name: "МГТУ"
  faculty: "Факультет информатики и систем управления"
  department: "Кафедра ИУ-7"

student:
  full_name: "Иванов Иван Иванович"
  short_name: "Иванов И. И."
  group: "ИУ7-41Б"

location:
  city: "Москва"
  year: "2026"
```

### Шаг 2. Создайте папку для новой работы
Создайте директорию в `Input/` со следующим порядковым номером (например, `Input/3/`):
- `Input/3/images/` — сохраните сюда скриншоты выполнения (терминалы, настройки, графики, схемы).
- `Input/3/extra/` — поместите исходники программ, конфиги, дампы или лог-файлы.
- `Input/3/Work.pdf` (или `.docx`) — методичка или текст задания.

### Шаг 3. Заполните параметры конкретной работы
В файле `Input/3/information.txt` укажите дисциплину и преподавателя:

```yaml
assignment:
  discipline: "Сетевые технологии"
  work_type: "Лабораторная работа"
  work_number: "3"
  work_topic: "Настройка статической и динамической маршрутизации OSPF"
  variant: "12"

instructor:
  title: "доцент, к.т.н."
  full_name: "Петров Петр Петрович"
  short_name: "Петров П. П."
```

### Шаг 4. Запустите генерацию через AI-агента
В используемой агентной среде (например, Antigravity CLI) дайте агенту команду на генерацию отчета. Агент выполнит шаги согласно [`AGENT.md`](file:///C:/Users/dvolj/Desktop/Ockta_docs%20git/AGENT.md):
1. Выберет последнюю папку `Input/[N]`.
2. Проанализирует скриншоты и сопутствующие файлы.
3. Сопоставит пункты задания с шагами выполнения.
4. Сгенерирует готовый `.docx` документ в `Output/[N] - [Тема]/`.

## 📑 Стандартная структура генерируемого отчета

1. **Титульный лист:** полное оформление шапки, реквизитов кафедры, исполнителя и проверяющего без плейсхолдеров (без нумерации страниц).
2. **Цель и задачи работы:** четкая формулировка на основе методички.
3. **Краткие теоретические сведения:** лаконичная выжимка ключевых определений и принципов, строго относящихся к теме.
4. **Ход выполнения работы (Практическая часть):**
   - Пошаговое описание действий от третьего лица в безличном стиле (*«было выполнено конфигурирование...»*).
   - Выполненные команды в виде отдельного курсивного текста.
   - Иллюстрации с автоматическими подписями (*«Рисунок [N] — [Описание]»*) и ссылками в тексте.
5. **Ответы на контрольные вопросы** (если они предусмотрены в задании).
6. **Вывод:** развернутый аналитический итог, отражающий достижение поставленных целей.
7. **Список использованных источников / Приложения** (при необходимости).

## ⚙️ Технические требования к форматированию

| Параметр | Требование |
|---|---|
| **Формат листа** | A4, книжная ориентация (Portrait) |
| **Поля страницы** | Левое: 30 мм, Правое: 15 мм (или 10 мм), Верхнее: 20 мм, Нижнее: 20 мм |
| **Основной шрифт** | Times New Roman, 14 pt (или 12 pt по правилам ВУЗа) |
| **Межстрочный интервал** | Полуторный (1.5) |
| **Абзацный отступ** | 1.25 см |
| **Выравнивание** | По ширине (Justified) |
| **Команды консоли** | Без таблиц, без шелл-префиксов (`$`, `#`), каждая на новой строке, стиль *курсив* |
| **Подписи к рисункам** | По центру, под рисунком: *«Рисунок X — Название»* (12 pt, одинарный интервал) |
| **Таблицы** | Заголовок слева над таблицей: *«Таблица X — Название»*, шрифт 10–12 pt |

## 🛠️ Зависимости и инструменты

Для ручной сборки или скриптовой модификации документа агентом могут использоваться:
- Python 3.10+
- `python-docx` — сборка и редактирование документов `.docx`
- `Pillow` — анализ и манипуляции с графическими материалами
- `PyPDF2` / `pdfplumber` / `pypdf` — извлечение текста из заданий в формате PDF
